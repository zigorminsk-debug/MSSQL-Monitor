# MS SQL Monitor — мониторинг и диагностика MS SQL Server

Программа для **контроля работы MS SQL Server**: потребление ресурсов, скорость обработки
запросов, настройки экземпляра. По результатам — **подробный HTML-отчёт с графиками
загрузки за сутки, разбором причин замедления и рекомендациями** по устранению проблем
(с готовыми SQL-скриптами исправлений).

Возможности:

- 📊 **Суточный мониторинг** — опрос сервера каждые 30 сек (настраивается), история
  хранится в SQLite до 7 дней; графики загрузки ЦП, Batch/sec, ввода-вывода, PLE,
  ожиданий и блокировок за 24 часа.
- 🔍 **Анализ причин замедления** по методологии ожиданий (waits): категории
  ЦП/память/диски/блокировки/сеть с доказательствами и конкретными шагами.
- ⚙️ **Аудит настроек**: max server memory, MAXDOP, cost threshold, tempdb, autogrowth,
  recovery-модели, резервные копии, VLF, авто-сжатие/закрытие БД и др.
- 🩺 **Рекомендации**: приоритезированы (Критично / Важно / Рекомендуется), к каждой —
  готовый T-SQL скрипт исправления.
- 📈 **Индексы и статистика**: недостающие индексы (с CREATE INDEX), фрагментация,
  устаревшая статистика.
- 🐛 **Отслеживание блокировок** (head-blocker + запросы жертв) и медленных запросов.
- 📄 **HTML-отчёты**: самодостаточные файлы (работают без интернета), печать в PDF.
- 🧪 **Демо-режим** — посмотреть всю аналитику без реального сервера.

## Быстрый старт (без сборки)

Нужен Python 3.11–3.13 (https://python.org, при установке отметьте *Add to PATH*):

```bat
pip install -r requirements.txt
python main.py
```

## Сборка EXE (Windows)

1. Установите Python 3.11–3.13.
2. Запустите **`build.bat`** (двойной клик).
3. Готово: **`dist\MSSQLMonitor\MSSQLMonitor.exe`** — папку можно переносить целиком
   на любой сервер/рабочую станцию Windows.

Сборка автоматически: создаёт окружение, ставит зависимости, проходит самопроверку
на демо-данных, генерирует иконку и собирает EXE через PyInstaller.

Альтернатива без локальной сборки — GitHub Actions: запушьте репозиторий, воркфлоу
`.github/workflows/build-exe.yml` соберёт EXE автоматически (Artifact «MSSQLMonitor»).

## Подключение

- **Windows-аутентификация** (доменная) или **SQL-логин/пароль**.
- Указывайте сервер как `ИМЯ` или `ИМЯ\ЭКЗЕМПЛЯР`; порт — при нестандартном
  (программа сама подставит `ИМЯ,ПОРТ`).
- Драйверы: используется `ODBC Driver 18/17 for SQL Server` (рекомендуется
  [установить](https://learn.microsoft.com/sql/connect/odbc/download-odbc-driver-for-sql-server)),
  при отсутствии — штатный «SQL Server», при отсутствии pyodbc — pymssql.
- Для полного снимка учётной записи нужны права `VIEW SERVER STATE` и чтение `msdb`:
  ```sql
  GRANT VIEW SERVER STATE TO [домен\пользователь];
  USE msdb; EXEC sp_addrolemember 'db_datareader', 'домен\пользователь';
  ```

## Как пользоваться

1. **Подключитесь** (или нажмите «🧪 Демо-режим», чтобы увидеть отчёт на примере).
2. Нажмите **«▶ Начать суточный мониторинг»** — программа копит статистику (чем дольше,
   тем полнее суточные графики; окно можно свернуть, программа продолжает работать).
3. В любой момент: **«📸 Полный снимок + отчёт»** (мгновенная диагностика) или
   **«📄 Суточный отчёт (24 ч)»** (полный разбор за сутки).
4. Настройки (⚙): интервал опроса, порог медленных запросов, время автоматического
   суточного отчёта, глубина хранения, глубокий анализ индексов.
5. Отчёты лежат в папке `data\reports`, список — на вкладке «Отчёты».

## Что анализируется

| Область | Источники (DMV) |
|---|---|
| ЦП, сессии, счётчики | `sys.dm_os_ring_buffers`, `sys.dm_os_performance_counters` |
| Ожидания (узкие места) | `sys.dm_os_wait_stats` (с фильтрацией «нерабочих» ожиданий) |
| Активные запросы, блокировки | `sys.dm_exec_requests/sessions`, `sys.dm_exec_input_buffer` |
| Ввод-вывод файлов | `sys.dm_io_virtual_file_stats`, `sys.master_files` |
| Память | `sys.dm_os_sys_memory`, `sys.dm_os_sys_info` |
| Настройки | `sys.configurations`, `sys.databases` |
| Топ запросов | `sys.dm_exec_query_stats` |
| Индексы/статистика | `sys.dm_db_missing_index_*`, `dm_db_index_physical_stats`, `dm_db_stats_properties` |
| Резервные копии, VLF | `msdb.dbo.backupset`, `sys.dm_db_log_info` |

Рекомендации — отправная точка: перед применением скриптов (`CREATE INDEX`,
`sp_configure`, `ALTER DATABASE`) проверяйте их на тестовой среде.

## Частые вопросы

- **«Ошибка входа 18456»** — неверный логин/пароль; для доменной аутентификации
  запустите программу под доменной учётной записью.
- **«Не удалось подключиться»** — проверьте, что SQL Server запущен, разрешён протокол
  TCP/IP (SQL Server Configuration Manager) и открыт порт 1433/ваш порт.
- **Отчёт пустой / мало данных** — недостаточно прав (`VIEW SERVER STATE`) либо
  мониторинг не был запущен (графики строятся по накопленной истории).
- **Антивирус ругается на EXE** — это PyInstaller-упаковка без подписи; при желании
  подпишите файл своей корпоративной подписью.
